# analyze-site

Босс приносит домен и вопрос: годится или нет. Внешне сайты выглядят одинаково — «бесплатные модели», список из четырёхсот имён, красивая панель. Разница обнаруживается только запросами, и обнаруживается поздно: у aihubmix 49 моделей с ценой 0/0 оказались десятью вызовами на весь аккаунт, а стену видно не по HTTP-ошибке, а по обычному `200 OK` с текстом внутри `content`.

Поэтому порядок работы построен так, чтобы дорогие шаги шли последними, а дешёвые отсеивали как можно больше.

## Что именно мы ищем

Критерий Босса, дословно: «Ну так же как вот этот сайт, только например не 10 дает, а 1000 к примеру дает реквестов». Десять запросов — «на зубок», интерес начинается с сотни-тысячи на аккаунт, потому что тогда имеет смысл просить друзей завести ещё аккаунтов.

Годится любая из четырёх форм щедрости:

- **множитель 0** — группа моделей, которая вообще не списывает баланс (`本分组0倍率，不扣除任何余额`). Лучшая форма: счёта нет;
- **стартовый баланс** — деньги на счёте после регистрации, которых хватает на сотни запросов;
- **лимит в запросах в минуту** — типично для 公益站, годится, если станция жива;
- **ежедневный бонус** — `checkin_enabled` в панели, «Ежедневный вход», отсюда же растёт баланс на gorouter.app.

Партнёрка интересна ровно как способ увеличить стартовый баланс. Позиция Босса: «Если они нас попросят к ним партнеров приводить за деньги, тогда мы посмотрим. Если нам выгодно будет, мы согласимся».

Ставку смотреть **раздельно**: сколько дают нам за голову и сколько получает приглашённый.
У tokenbom нам 200–250 credits, а приглашённому 750 — то есть ценность почти вся на стороне
новых аккаунтов из нашего пула, а не в нашей ставке, и считать выгоду надо от неё.
Там же проверять потолок приглашений: пятьдесят пожизненно — это верхняя граница всей затеи.

И отдельно: **цифра из объявления обычно не подарок за регистрацию**. Босс пришёл на tokenbom
за обещанными «10 $» — это оказался приз за первое место в месячном рейтинге пригласителей
(5000 credits), а за регистрацию без инвайт-ссылки дают ноль. Прежде чем считать станцию
щедрой, найти, **при каком условии** названа эта сумма.

## Ход работы

### 1. Просев без регистрации

```bash
uv run --no-project python .claude/skills/analyze-site/scripts/probe_public.py <домен> [ещё домены]
```

Скрипт спрашивает у домена только публичные GET и печатает: какая панель, `quota_per_unit`, открыта ли регистрация, нужен ли email и капча, есть ли чек-ин, чем ограничен вход (LinuxDO trust level, код регистрации, инвайт), сколько моделей отдаёт шлюз без ключа, и — главное — **объявления владельца целиком**.

Объявления читать обязательно. Условия щедрости живут именно там, а не в описании каталога: группу `complimentary` с нулевым множителем на api.42w.shop видно только из объявления от 22 июня. Там же встречаются и запреты: у ai.121628.xyz прогон бесплатных моделей «на живость» наказывается случайным баном.

На этом шаге отсеиваются мёртвые, закрытые на регистрацию и брошенные (объявления полугодовой давности в духе «暂时停止使用吧» — хозяин ушёл). Дальше идут только выжившие.

### 2. Внутрь панели

Регистрируется Босс руками — капчи, OAuth и подтверждения ящика не наша работа. От него нужны две строки со страницы `/profile`: **«Токен доступа»** и **«ID пользователя»**. Так и просить, этими словами; в терминах базы это `access_token` и `panel_id`.

Одного токена не хватает: New API требует ещё заголовок `New-Api-User: <panel_id>`, и с чужим id тот же токен получает 401. Ни один эндпоинт не отдаёт id по токену — отсюда и просьба.

```bash
uv run --no-project python .claude/skills/analyze-site/scripts/panel_info.py <домен> <access_token> [panel_id]
```
Скрипт печатает профиль, баланс в валюте сайта и в долларах, группу, счётчик запросов, доступные группы моделей с их множителями, состояние партнёрских эндпоинтов и — по флагу `--make-key` — создаёт API-ключ.

Детали панелей, отличия New API от One API и полный список эндпоинтов — `references/newapi-panel.md`.

**Если панели New API нет** (`probe_public.py` отдаёт «панели нет: HTTP 404», в исходнике страницы
Vue/Next вместо привычной разметки) — не бросать разбор, а искать свой способ авторизации.
Порядок, который сработал на anymodel.org и ai-router.dev: скачать бандл SPA и найти в нём
базовый адрес API (`const Ns="https://api.<домен>/api/v1"`) и то, откуда берётся токен. Дальше
два случая:

- **cookies сессии** (anymodel) — просить у Босса экспорт cookies. Там же нашлось, что `/api/me`
  по cookies отдаёт полный ключ и баланс одним запросом, хотя в UI ключ обрезан;
- **JWT в localStorage** (ai-router.dev, `localStorage.getItem("auth_token")`; tokenbom.com,
  `accessToken`) — cookies дают 401 `Authorization header is required` или отсутствуют вовсе,
  и экспорт cookies бесполезен. Просить так: на открытой
  странице сайта F12 → вкладка Application → Local Storage → адрес сайта → строка `auth_token`,
  скопировать значение. Дальше запросы идут с обычным `Authorization: Bearer <jwt>`.
  Имя ключа у каждой платформы своё, поэтому просить **весь список** Local Storage, а не
  конкретную строку. Заголовки вида `x-device-fingerprint` и `x-env-signature` рядом в бандле —
  косметика, повторять их не нужно.

Такой JWT живёт часы, поэтому в `access_token` записи его **не кладём** — к утру он мёртв
и только запутает. Вместо этого в `meta.panel_read` пишем набор эндпоинтов, которым читается
станция: где баланс, где списания, где полное значение ключа. У tokenbom, например,
`/api/virtual-keys` отдаёт `fullKey` открытым текстом — значит ключ восстановим всегда,
и терять его не страшно.

### 2а. Биржа чужих подписок — отдельный тип, не релей

Признак в бандле: эндпоинты сдачи **своего** ключа (`/keys`, `/keys/preflight`,
`/keys/scan-models`), правила маршрутов на адреса вендоров (`codingPlanUrlRules`), учёт
по каналам (`/metering/provider-channel-stats`, `switch-provider`, `unblock-provider`).
Так устроены ai-router.dev и tokenbom.com.

Разбирать такую станцию иначе, потому что ломается главное допущение: **каталог не равен
поставке**. Модель числится в прайсе, а поставщика под неё сейчас нет — ответ
`model_supply_empty` или `overloaded_error` штатный, не поломка. Отсюда правила:

- каждую интересную модель щупать **живым вызовом**, и мёртвую **переспросить позже**:
  поставка возвращается по остыванию лимитов (у tokenbom `claude-4.8-opus` ожил со второй
  попытки, а sonnet — нет в обоих прогонах);
- в `meta.price` заводить только то, что ответило. Иначе `find_model.py` начнёт обещать
  Боссу модели, которых сегодня нет;
- сверять **накладные токены**: канал приклеивает системный промпт того coding-plan, который
  сдал поставщик. У tokenbom это 6886 входных токенов на «2+2», то есть 0.7 цента ни за что.
  Смотреть `usage.prompt_tokens` на коротком запросе — это и есть размер накладных;
- рядом с рейтингом обычно висит признание владельца о каналах, отдававших **не ту модель,
  что обещано**. У tokenbom оттуда же взялись 500 credits компенсации на аккаунте Босса.
  Такое признание — не довод против станции, а мера её честности, но цену модели после него
  проверять только своим вызовом.

### 2б. Когда счёт в credits, а не в деньгах

Курс не публикуют, но он выводится из товарной сетки: у tokenbom 5000 credits за 1000 центов,
то есть credit = 0.002 $. Дальше `inputPriceCredits`/`outputPriceCredits` читаются как
**credits за 1M токенов**, и всё сводится к долларам за миллион, как у остальных станций.

Проверять множители тарифа: цена по прайсу — не то, что списали. У tokenbom дешёвые модели
идут по уровню `economy` со множителем **0.8**, дорогие — по `standard` без скидки. Видно это
только сверкой списания (`/api/metering/consumer-model-stats` отдаёт `creditsCharged` и `tier`
по каждой модели) с прайсом. И ровно так же вскрывается ложь прайса: `gpt-image-2` заявлен
`0/0`, а списал 0.693 credits за картинку 1024×1024.

Босс оценил этот приём отдельно («то, что можно взять токены из Local Storage, это вообще
гениальный ход»), так что применять его на любой не-New-API панели, а не искать каждый раз заново.

### 3. Тест моделей

**Последовательно, по приоритету, малым числом запросов.** Это не осторожность ради осторожности: на aihubmix параллельный прогон 49 моделей в десять потоков сжёг лимит аккаунта на алфавитно первых моделях, и до Gemini очередь не дошла — Босс справедливо указал: «Надо было вам Gemini проверять». А на некоторых станциях за такой прогон бан.

```bash
uv run --no-project python .claude/skills/analyze-site/scripts/bench_model.py <base_url> <ключ> <модель> [ещё модели]
```

Задача теста — настоящая задача проекта: из письма достать отправителя, код и срок действия, вернуть чистый JSON. В письме нарочно лежат посторонние шестизначные числа, поэтому модель, которая хватает первое попавшееся, проваливается. Методика, эталонный промпт и разбор вердиктов — `references/model-testing.md`.

Какие модели брать первыми: **список нужных нам моделей задан заранее** — `references/wanted-models.md`. Порядок такой: `claude-opus-5` (на ней работает Босс, без неё станция не провайдер сессии), видео, дешёвые картинки, модели под задачи проекта. Указание Босса дословно: «У нас есть список моделей, которые прямо для нас очень необходимы. Вот их надо в первую очередь проверить, а всё остальное — это уже если сайт вообще какой-то бедный, либо у него есть какие-то модели слишком редкие». Каталог, в котором нет ни одной нашей модели, ценности не имеет, сколько бы имён в нём ни числилось.

Редкость — второй повод для вызова: сверить каталог с первой двадцаткой рейтинга `https://arena.ai/leaderboard/code/webdev` (открывается без логина, обновляется до нескольких раз в день — смотреть заново) и с нашим коридором цен через `scripts/find_model.py`. Модель из двадцатки, которой у нас нет, — кандидат на прогон.

Отдельно смотреть **генерацию картинок**: каталоги станций почти целиком текстовые, и `gpt-image-2`
нашлась только на двух из десяти наших сайтов. Искать в `/api/pricing` по `image` и `gpt-image`,
проверять живым вызовом `POST /v1/images/generations` — присутствие модели в каталоге ничего
не значит, у fujcloud целая группа `image` мертва при живой модели в `default`. Сводка по нашим
станциям — в памяти `project_image_models.md`.

Брать **2–3 модели, где прикидка по прайсу дала лучшую выгоду**, и обкладывать прогон вызовами `panel_info.py` до и после: прайс станции — это заявление, а Δ`used_quota` — факт. По этой разности и считается настоящая цена запроса, из которой потом растёт вердикт (`references/verdict.md`, раздел про две стадии).

### 4. Блоги, форумы и документация

Шаг дешёвый и делается параллельно с остальными: сеть знает про станцию то, чего она сама
про себя не пишет — что каналы мертвы, что владелец обнулил балансы, что домен перепродаёт
чужой шлюз.

- **LinuxDO** (`linux.do`) — родина 公益站. Владельцы там же и объявляют раздачи, там же
  пользователи жалуются. Если у станции `linuxdo_oauth`, тема про неё на форуме почти
  наверняка есть.
- **`https://docs.<домен>/llms.txt`** — индекс всех страниц документации одним файлом.
  Искать иероглифы `邀请` (приглашение), `返利` (кэшбэк), `推广`, `联盟`, `分销` — так находятся
  партнёрские условия, которых нет в панели.
- **Отзывы** — через скилл `agent-reach`. Полезные запросы: домен плюс `跑路` (сбежал),
  `倒闭` (закрылся), `骗` (обман), плюс просто имя станции для свежих обсуждений.

Читать критически. Блог вендора обещал «по 10 вызовов на каждую модель» — живой прогон дал
10 на весь аккаунт. Заявления проверяются запросами, а форум годится ровно на то, чтобы
не тратить эти запросы впустую.

### 5. Вердикт

Сводится к одному: сколько запросов мы реально получим и чем это подтверждено. Форма ответа Боссу, стоп-признаки и порядок заведения в базу с машиночитаемым прайсом — `references/verdict.md`.

Прежде чем начинать, посмотри `references/known-sites.md`: там сводка по уже разобранным сайтам с причинами отказа. Половина новых доменов оказывается перепродажей уже отклонённого — zlkpro.tech перепродавал aihubmix, и это выяснилось только по тексту заглушки со ссылкой на чужой топап.

## Стоп-признаки

Каждый стоил нам времени, поэтому проверять их дёшево и обязательно.

**Заглушка приходит как `200 OK`.** Не как ошибка. Обычный `content`, id вида `chatcmpl-fake-<timestamp>`. Автоматика примет её за ответ модели, если не читать текст. Всегда сверяй `content` с ожидаемым видом ответа.

**Предоплата за доступ к партнёрке.** gpt.ge открывает реферальную программу только после пополнения. Это отказ: платить за право приводить людей мы не будем.

**Накладные токены.** zlkpro списывал ~2000 токенов на запрос сверх промпта, kimi — фиксированно 2000. Сравнивай `usage.prompt_tokens` с длиной своего промпта: расхождение в разы означает, что «дешёвая» цена за миллион ничего не значит.

**Подписки вместо баланса.** Если панель продаёт план, а не квоту, наши приёмы (много аккаунтов с малым балансом) не работают.

**Пустой `content` при полном `completion_tokens`.** Модель ушла в рассуждения и сожгла лимит вывода. Формально жива, практически бесполезна — так вели себя `coding-glm-4.6/4.7-free`.

**`<think>` в ответе.** Чистый JSON не отдаёт, для нашей задачи не годится без постобработки.

**Админская подсистема против накрутки приглашений.** Не стоп-признак для станции, а стоп-признак
для **масштабирования**. Смотреть в бандле: `/admin/invite-violations`,
`/admin/invite-violations/freeze-revoke`, `/admin/invite-policy` плюс пользовательская ручка
`/invite-violation-notice` и готовый текст «нарушение при регистрации, начисленное изъято».
Если это есть — заводить один-два аккаунта и не гнать пул: обещание заморозить все связанные
аккаунты без разблокировки написано не для красоты, а связать наши регистрации с одного адреса
у них выходит одним запросом. Массовый заход отложить до мобильного ротационного прокси.

## Чего не делать

**Не гонять модели параллельно.** Лимит бесплатных попыток заранее неизвестен, а расходуется он необратимо.

**Не верить документации вендора.** Их блог обещал «по 10 вызовов на каждую модель», живой прогон дал 10 на весь аккаунт. Заявления проверяются запросами.

**Не заводить сайт в базу до вердикта.** Отклонённые сайты в `main_site` не заводим вовсе — про них остаётся запись в памяти.

**Не тратить лимит на разведку схемы.** Сначала публичные GET, потом панель, и только потом реальные вызовы моделей — в этом порядке ровно потому, что необратим только последний шаг.

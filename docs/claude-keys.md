# Ключи Claude Code: балансы, ротация, чек-ин

## Мониторинг балансов станций Claude Code

`scripts/gorouter_balance.py` (имя историческое, gorouter он давно не единственный) снимает
остаток, расход за 24 часа и запас по дням со **всех станций, куда Claude Code может ходить** —
это записи `main_site`, у которых заполнен `meta.endpoints_anthropic` и не стоит
`meta.blocked`. На 2026-08-23 их две: gorouter.app и tabitoken.com. Список не зашит в код:
появится третья станция с этим ключом в `meta` — скрипт подхватит её сам. Пишет
`log/gorouter_balance.txt` секциями по станциям. В кроне — `7,22,37,52 * * * *`,
вывод в `log/gorouter_balance_cron.txt`.

`meta.blocked: true` — станция закрыла нам доступ, идти туда нечем: `load_stations()` её
пропускает, поэтому она не попадает ни в отчёт, ни в снимок, ни в кандидаты на ключ.
Метку ставит Босс (у сайтов своей колонки `active` нет, `active` есть только у аккаунтов),
а не скрипт по ответу станции: 401 бывает и временным, по одному прогону бан от сбоя
не отличить. Рядом лежат `blocked_at` и `blocked_note` — причина и дата. Адрес, прайс
и аккаунты при этом сохраняются: знание о станции не теряем, разблокируют — снимем метку.
Так 2026-08-23 выпала vyceai.com: страница «Account access is temporarily restricted /
Review required», все наши ключи отдают 401 `invalid_api_key`, сессии панели — 401
`invalid_session`; апелляцию в Discord решили не подавать, чтобы не привлекать внимание
к остальным аккаунтам.

Аккаунты берутся из **обеих** таблиц (`main_site_account` и `main_site_account_custom`) —
кандидатом считается любая запись с непустым `token`, потому что `token` и есть ключ для
Claude Code. Остаток снимается четырьмя способами, и рейтинг `rank()` доверяет им в этом
порядке (`TRUST`, поле `source` у кандидата):

1. `panel` — панель New API с парой `access_token` + `panel_id`: свежая цифра, пишется в базу.
2. `session` — своя панель станции по сессии из браузера (`meta.panel_api = "vyce"`): реальный
   остаток, считать ничего не нужно, пишется в базу. См. ниже.
3. `usage` — станции без панели: расход ключа отдаёт сам API, см. ниже. Тоже пишется в базу.
4. `db` — расход не читается и панели нет: цифра из базы, в отчёте помечена «остаток из базы,
   свежесть не гарантирована».

**Станция со своей панелью читается её же сессией.** Признак — `meta.panel_api` (`"vyce"`
у vyceai.com), а не наличие `panel_id`: тип панели по её ответу не угадать, зато при разборе
сайта он известен. Сессия лежит в браузере в localStorage под ключом `vyce_session`, живёт
около недели, и Босс копирует её в `access_token` записи (F12 → Application → Local Storage).
Программного входа нет: `POST /user/login` требует одноразовый токен Cloudflare Turnstile
из живой страницы и отпечаток устройства. Эндпоинты — `GET /user/dashboard`
(`stats.availableBalance`, `totalSpent`, `totalRequests`, массив `keys`), `GET /user/balance`,
`GET /user/referral` (партнёрский доход, в API по ключу не виден). Авторизация —
`Authorization: Bearer <сессия>`, cookies и `panel_id` не нужны. Истёкшая сессия даёт 401 —
тогда в отчёте стоит строка «впишите в access_token свежее значение vyce_session», а остаток
на этом прогоне считается по расходу ключа, как раньше: без цифры Босс не останется.

**Дневной подарок забирается тем же ключом** (`vyce_claim_daily()`): `GET /user/daily-reward`
и, если `canClaim`, `POST /user/daily-reward/claim` — без тела, csrf у панели заведён только
под вход и регистрацию. У vyceai это 25 $/сутки со стриком. Клейм идёт **до** чтения остатка,
иначе в базу уехала бы цифра без подарка. Отказ клейма прогон не валит и печатается строкой:
окно суточное, прогонов 96, следующий доберёт.

**Остаток без панели считается по расходу самого ключа** — ни панель, ни cookies не нужны.
Cookies Босс отверг сам: срок их жизни неизвестен, и одной сессией несколькими аккаунтами
станции не рулить. Расход спрашивается тем же ключом, которым ходит Claude Code
(`read_usage()`), двумя формами: у New API — `GET /v1/dashboard/billing/usage` с широким окном
дат, `total_usage` в **центах** (сверено с панелью на трёх аккаунтах, разница 0.00);
у vyceai — `GET /v1/me`, `totalSpent` в долларах, а `balance` там это лимит самого ключа
(0 = без лимита), не деньги аккаунта. Кто перед нами, видно по ответу: vyceai на билинговый
путь отдаёт HTML главной страницы с кодом 200, поэтому не-JSON и отсутствие нужного поля
трактуются как «не тот формат, пробуем следующий».

Расход — не остаток, нужна точка отсчёта (`derive_balance()`):
`остаток = остаток_калибровки − (расход_сейчас − расход_калибровки)`, где калибровка это цифра,
которую Босс вписал в базу руками. Она лежит в `log/gorouter_balance_state.json`
(`calib_spent`, `calib_balance`, `written`, `spent`, `api`). Заново калибруемся в трёх случаях:
калибровки ещё нет; в базе стоит не то, что записали мы (значит Босс пополнил счёт или
поправил руками — пополнения в расходе не видны); расход стал меньше прежнего (счётчик станции
сбросили). Ниже нуля остаток не уходит. Слабое место осознанное: бонусы чек-ина и пополнения
скрипт узнаёт только через правку баланса в базе.

Полный прогон на 68 аккаунтах занимает около двух минут, из них 45 запросов расхода —
последовательно; при шаге крона 15 минут этого хватает.

**Партнёрские дела балансер ведёт сам**, чтобы не запускать `panel_sync.py` руками. У аккаунтов
с парой `access_token` + `panel_id`:

- `aff_transfer()` перекладывает `aff_quota` в основной баланс (`POST /api/user/aff_transfer`).
  Иначе партнёрские деньги висят в кармане со статусом «ОЖИДАЕТ» и на запросы не тратятся.
- `update_aff()` проставляет запись `aff` полной ссылкой `https://<станция><путь>?aff=<код>`:
  `aff_code` отдаёт только панель, а в базе у части аккаунтов лежал один код (`2PeJ`), который
  без домена никуда не вставить. Путь берётся из ссылок, что Босс уже скопировал руками для
  этой станции (`aff_paths()`), иначе `/sign-up` — по HTTP его не узнать, и `/sign-up`,
  и `/register` отдают одну оболочку SPA с кодом 200. Владелец сверяется по `display_name`,
  как и у баланса: токены вставляются руками, опечатка иначе перепишет чужую строку.

`panel_sync.py` остался для ручной сверки и пересчёта `cnt`, но по партнёрке кроном теперь
всё делается само.

Панель New API имеет две неочевидности. Первая: `/api/user/self` требует не только
`Authorization: Bearer <access_token>`, но и заголовок `New-Api-User: <panel_id>` — без него
401, с чужим id тоже 401. Из токена id не выводится ни одним эндпоинтом, поэтому обе строки
берутся со страницы `/profile` руками и лежат в базе. Вторая: Cloudflare пропускает только
User-Agent Chrome Босса, с чужим UA вместо JSON приходит заглушка. Поэтому версия Chrome
в скрипте — константа, её меняют при обновлении браузера.

Суммы считаются делением `quota` на `quota_per_unit` из `/api/status` (500000 за доллар),
расход за сутки — суммой по `/api/data/self`. Адрес панели — `https://<main_site.name>`,
он же домен станции; Anthropic-адрес из `meta.endpoints_anthropic` идёт только в настройки
Claude Code.

Токен панель копирует в буфер с хвостовыми пробелами, отсюда `strip()`. Перед записью баланса
сверяется `display_name` из панели с `login` записи: токены вставляются руками, и опечатка
иначе молча перезапишет баланс чужой строки. Последние удачные цифры лежат в
`log/gorouter_balance_state.json` (ключ — `<таблица>:<id>`, старые чистые id мигрируют
на лету): когда токен отзывают, вместо блока печатается `!!! ОШИБКА ОБНОВЛЕНИЯ` с последним
известным остатком и его возрастом в часах — иначе Босс потеряет ориентир по деньгам ровно
в тот момент, когда он нужнее всего. Аккаунт, у которого пара доступов есть, а панель отказала,
из кандидатов на ключ **исключается**: скорее всего он забанен или токен отозван.

Cookies больше не нужны: экспорты `data/gorouter.app_cookies*.json` не читаются, и срок жизни
сессии ни на что не влияет.

### Ротация ключа Claude Code

Тот же прогон крутит ключи. Активный ключ лежит в `~/.claude/gorouter_key` (0600), его
печатает `~/.claude/bin/gorouter-key.sh`, а он прописан в `~/.claude/settings.json` как
`apiKeyHelper`. Когда у активного аккаунта остаётся меньше `ROTATE_BELOW` (15 $), файл
переписывается на самый богатый аккаунт **любой** станции. Порог привязан к шагу крона:
самая дорогая наблюдавшаяся полчаса — 19.50 $ за 70 запросов, то есть около 10 $ за четверть
часа, поэтому при шаге 15 минут 15 $ хватает с запасом. При равных деньгах впереди тот, чья
цифра надёжнее: панель > расчёт по расходу ключа > цифра из базы (`TRUST`).

**Главная проверка прогона — станция, на которой сессия сидит прямо сейчас.** Порог
второстепенен: станция может лежать при полном счету, и тогда сессия парализована до тех пор,
пока ключ не переставят. Поэтому `rotate_keys()` сначала щупает `GET /v1/models` (`probe()`)
по `meta.endpoints_anthropic` активной станции активным ключом. Ответ есть → дальше прежний
порядок со сверкой `ROTATE_BELOW`. Ошибка ≥400, 522 или таймаут → ключ и endpoint
переключаются **принудительно, независимо от баланса**; это исключение из правила порога.

Щупается именно Anthropic-адрес, а не панель баланса: это разные точки отказа (панель может
лежать при живом API и наоборот). Проба бесплатна, список моделей тарифом не считается. Заодно
она разделяет два случая по коду ответа: 401/403 — `kind: "key"` (ключ отозван или кончилась
квота, станция при этом жива), остальное — `kind: "station"`. В отчёте это разные строки,
поворот нужен в обоих.

**Мягкий отказ переспрашивается**: `probe()` повторяет попытку `PROBE_TRIES` (3) раза с паузой
`PROBE_PAUSE` (4 с), а 401/403 не повторяет — это окончательный ответ. Без ретраев ключ мотался
gorouter↔tabitoken каждые 15 минут: разовый 5xx и `ConnectionError: Network is unreachable`
неотличимы от падения станции, если спросить один раз. Отказ на сетевом уровне помечается
`net: True`, и если по сети не ответила **ни одна** станция, скрипт не трогает ни ключ, ни
настройки, ни метки: станции сразу все не падают, значит лежит наша сеть или proxy (у крона
нет прокси-переменных оболочки).

**Список моделей врёт о готовности**, поэтому цель поворота проверяется живым вызовом
(`probe_call()`, `POST /v1/messages` с `max_tokens: 1`): 23.08 у vyceai `claude-opus-5` стоял
в `/v1/models`, а вызов отвечал `503 model_maintenance` — сессия поднялась бы мёртвой. Вызов
делается только для цели поворота: на тарифе за запрос (gorouter 0.30 $) проверка на каждом
прогоне стоила бы под 29 $ в сутки. 429 считается годным ответом — модель есть, просто занята.

Цель поворота ищет `pick_target()`: идёт по рейтингу `rank()` и щупает кандидатов, пока не
найдёт живого; станция, ответившая `kind: "station"`, дальше не переспрашивается. Число проб
ограничено `MAX_PROBES` (6) — прогон стоит в кроне каждые 15 минут, упираться в таймауты всего
списка нельзя. Годная цель — живая станция, у которой есть и работает `claude_models.main` из
меты. Станции без своей основной модели целью не становятся вовсе; сценария «беру, но придётся
править настройки руками» больше нет — именно он 23.08 оставил Босса без сессии. Если живой
станции не нашлось — ключ и endpoint не трогаются: разбудить сессию нечем, а испортить
настройки можно.

Аккаунт с отказавшей панелью помечается `suspect` и остаётся в списке кандидатов, хотя целью
поворота не станет. Иначе при падении станции активный ключ выпал бы из списка и выглядел
«незнакомым» — то есть падение провайдера скрипт спутал бы с ручным переключением и не сделал
бы ровно того, для чего эта проверка заведена.

**Ключ, endpoint и имена моделей переключаются только вместе.** `env.ANTHROPIC_BASE_URL` один
на настройки, и ключ чужой станции по чужому адресу получает 401 — сессия умирает сразу. Именно
так вышло 23.08: Босс руками ушёл на tabitoken (и ключ, и адрес), а прежняя версия скрипта
вернула туда ключ от gorouter при адресе tabitoken. Поэтому теперь `ANTHROPIC_BASE_URL`
сверяется с `meta.endpoints_anthropic` станции активного ключа на **каждом** прогоне, а не
только в момент поворота: разъехавшуюся пару скрипт починит сам.

Вместе с ними `update_settings()` пишет `ANTHROPIC_DEFAULT_SONNET_MODEL`
и `ANTHROPIC_DEFAULT_HAIKU_MODEL` — из `meta.claude_models` станции (`station_models()`).
Это вторая причина той же комы: скрипт увёл ключ на vyceai, где нет `claude-opus-4-8` из
настроек, и все вызовы sonnet и haiku (субагенты, сжатие контекста) молча падали, пока Босс
не поднял сессию руками. Если объявленной в мете модели на станции по факту нет,
`effective_models()` подставляет в оба поля основную. Все правки идут одной атомарной записью
файла — промежуточный вариант работающей сессии ни к чему.

Незнакомый ключ в файле — сигнал не трогать вообще ничего, включая endpoint. Если содержимое
`~/.claude/gorouter_key` не совпадает ни с одним `token` в базе, значит Босс переключил Claude
Code руками на станцию, которой мы не знаем. Раньше скрипт в этом случае писал туда самый
богатый gorouter-аккаунт — то есть следующий прогон крона молча вернул бы сессию на станцию,
от которой Босс только что ушёл. Теперь `rotate_keys()` выходит с пометкой «переключено
вручную, не трогаю».

`env.ANTHROPIC_AUTH_TOKEN` держит **тот же ключ, что файл `apiKeyHelper`**, а никакой не
«резерв со второго по деньгам аккаунта». Порядок старшинства обратный тому, что считалось
раньше: `env` в `settings.json` > `apiKeyHelper` > экспорты в `~/.zshrc` (там прописан
tabitoken, он проигрывает всем). Проверено 25.08: прогон в 12:51 вписал в env второй аккаунт
станции, и уже идущая сессия перешла на него (54 запроса в ведре 13:00), тогда как аккаунт
из файла ключа простоял без обращений с 08:00 при полностью живом ключе — оба отвечали 200
на `/v1/models`. То есть настройки перечитываются на ходу и перебивают помощника. Пока там
лежал чужой аккаунт, деньги тратились не с того, на кого показывали и меню, и отчёт, — поэтому
идея отдельного резерва упразднена.

Ограничения, тоже проверенные опытом на 2.1.112. Файл ключа читается при старте сессии: его
подмена посреди работы **игнорируется**, пока старый ключ жив, и
`CLAUDE_CODE_API_KEY_HELPER_TTL_MS` этого не меняет — новый ключ подхватывает следующая сессия.
А вот `settings.json` перечитывается на ходу, отсюда и старшинство env. Сломанный ключ сессию
не убивает: на 401 она молча съезжает на другой токен из настроек. Но когда у аккаунта кончаются
деньги, New API отвечает **403** `insufficient_user_quota`, а не 401, так что этот путь
на исчерпание не срабатывает — ровно поэтому ротация упреждающая, по порогу, а не по ошибке.

Блок «Ключи Claude Code» в конце `log/gorouter_balance.txt` показывает основной ключ со
станцией, состояние endpoint, env-токен и метки. Метка в `note` едет за ключом: у активного
аккаунта скрипт держит `Claude`, у остальных чистит (включая прежнюю `Claude резерв`) — иначе
после ротации примечание Босса указывает на строку, с которой уже никто не ходит. Чужой текст
в `note` при этом не затирается: метка пишется только в пустое поле или поверх самой себя.

Проверено вживую 2026-08-20: подделанный нулевой баланс активного аккаунта повернул ключ
на следующий по деньгам, и свежая сессия пошла именно на него — счётчик запросов у записи 77
вырос с 22 до 23. Ротация вместе с endpoint прогнана 2026-08-23 на подставных данных
(`rotate_keys` с фейковыми станциями): поворот gorouter → tabitoken меняет и ключ, и адрес;
разъехавшаяся пара приводится к станции ключа; незнакомый ключ оставляет настройки нетронутыми.
Экстренный поворот прогнан тем же способом 2026-08-23: лежащая станция при 190 $ на счету даёт
поворот вместе с адресом, 403 по ключу при живой станции — тоже, «лежит всё» настройки не
трогает. Тем же приёмом 2026-08-23 прогнаны и новые ветки: поворот на vyceai переписывает оба
`ANTHROPIC_DEFAULT_*_MODEL` на `claude-sonnet-4-6`; при отсутствии объявленного sonnet
в оба поля уезжает `claude-opus-5`; `503` на живом вызове снимает станцию с рассмотрения;
сетевой отказ по всем станциям не меняет ни файла ключа, ни настроек. Состав моделей на 23.08:
gorouter и tabitoken — 4 модели (`claude-opus-4-8`, `claude-opus-5` и их `-thinking`),
vyceai — 10, но без `claude-opus-4-8`.

### Снимок станций и переключение из интерфейса

Тот же прогон пишет `log/claude_stations.json` (`snapshot_stations()`): по станции — живость,
`kind`, состав моделей, имена из `meta.claude_models`, лучший аккаунт с балансом и его `source`,
признак `active` и готовая метка `can_activate` (станция ответила, в моделях есть её
`claude_models.main`, по умолчанию `REQUIRED_MODEL = "claude-opus-5"`, на аккаунте не меньше
`ROTATE_BELOW`). Метку считает скрипт, а не эндпоинт: решение о годности принимает
тот, кто щупал станцию, и порог с именем модели лежат в одном месте. Без основной модели
станция негодна независимо от денег: Босс работает именно на ней.
`GET /api/claude/stations` отдаёт снимок как есть — ни проб, ни расчётов при открытии страницы.
Файлом, а не расчётом по запросу: живая проба стоит до `PROBE_TIMEOUT` на станцию, и страница
«Сайты» ждала бы минуту.

`active` считается по станции, а не по её лучшему аккаунту: сессия может сидеть и на небогатом
ключе, а значок «Активен» нужен у станции — иначе он не горел бы ни у одной.

`POST /api/claude/activate {site_id}` переключает сессию руками из интерфейса: импортирует
`scripts.gorouter_balance`, собирает аккаунты станции, щупает первые `MAX_PROBES` по рейтингу
и берёт первый живой с моделью `claude_models.main`, затем пишет ключ и зовёт
`update_settings()` — то есть ключ, `ANTHROPIC_BASE_URL` и оба `ANTHROPIC_DEFAULT_*_MODEL`
меняются одной атомарной записью, как при автоматической ротации.
404 — у сайта нет `meta.endpoints_anthropic`, 409 — нет аккаунтов с токеном либо ни один
не прошёл пробу. Подхватит новую станцию следующая сессия, текущая доработает на старом ключе.

### Статусная строка Claude Code

`scripts/statusline.py` прописан в `~/.claude/settings.json` как `statusLine` и рисует
`536 $ / 4 д 6 ч · ctx 42 % · субагент 1 · 07:41 ср 26 авг`: остаток и запас по времени
активного ключа (те же `balance` и `day_work`, что в таблице аккаунтов, — их считает балансер),
загрузка контекстного окна, число незакрытых субагентов, часы с днём недели и датой без года.
Каталог и модель не выводятся по прямому требованию Босса. Ради этого
`GET /api/claude/active` отдаёт ещё и `day_work`.

Проценты контекста красятся с 80 % в ярко-жёлтый, с 90 % — в ярко-красный (`\033[93m`
и `\033[91m`, 90-е коды: обычные 33/31 на тёмной теме тусклые). Так же красится запас
по времени: меньше 5 часов — жёлтый, меньше часа — красный. Выше порогов цвета нет вовсе,
иначе он перестаёт быть предупреждением. День недели и месяц берутся из своих списков,
а не из `%a`/`%b`: локаль у крона и оболочки разная, на C-локали в строку уехало бы `Wed`.

Зовётся `python3`, а не `uv run`: строка рисуется на каждый ответ, и `uv` добавляет к запуску
десятые доли секунды на пустом месте. Отсюда же чистый stdlib без зависимостей проекта.
Деньги кэшируются в `/tmp/claude-statusline-active.json` на `CACHE_TTL`, причём кэш по сроку
не выбрасывается, а только обновляется: когда backend лежит, вчерашняя цифра со звёздочкой
полезнее прочерка. Пустой вывод гасит строку целиком, поэтому все сбои проглатываются
и превращаются в `—`.

Штатного счётчика субагентов в главной строке у Claude Code нет (есть отдельная
`subagentStatusLine`), поэтому `pending()` считает их по хвосту JSONL-транскрипта: вызовы
`tool_use` минус пришедшие `tool_result` по `tool_use_id`. Читается последние `TAIL_BYTES`
(400 КБ) — файл сессии дорастает до десятков мегабайт, а незакрытые вызовы лежат в самом
конце. Имя инструмента в транскрипте — **`Agent`** (документация называет `Task`, поэтому
в `AGENT_NAMES` оба). Тесты — `tests/test_statusline.py`.

### Ежедневный чек-ин на станциях

`scripts/gorouter_checkin.py` (имя историческое) забирает суточный подарок панели New API
на **всех** станциях, а не только на gorouter.app. Кнопка «Войдите сейчас» живёт на
`/profile`, а `POST /api/user/checkin` закрыт Cloudflare Turnstile, поэтому единственный путь
— живой Chromium через `agent-browser` и вход по GitHub OAuth в отдельной сессии на каждый
аккаунт. Отсюда и требования к кандидату: `access_token`, `panel_id` и `github_id` —
без пары доступов не прочитать состояние чек-ина, без `main_github` нечем войти.

Станции ищет `load_stations()`: все `main_site` без `meta.blocked`, аккаунты из
`main_site_account` (у `custom` нет `github_id`, входить через OAuth там нечем). Список не
зашит в код — новую станцию с чек-ином скрипт подхватит сам.

Есть ли чек-ин и сколько он даёт, спрашивается у самой панели один раз на станцию
(`checkin_offer()`, первым её аккаунтом): `checkin_enabled` в `/api/status` плюс вилка
`min_quota`/`max_quota` в `/api/user/checkin`. Метка в базе для этого не нужна и размечать
станции руками не приходится. Подарок меньше `MIN_REWARD` (0.50 $) не берётся — прогон
одного аккаунта это живой браузер и минута-две времени, а у ai.mrcwoods.com чек-ин даёт
1000-2000 quota, то есть меньше половины цента. Пропуск при этом печатается строкой
`пропущено:`, чтобы решение было видно, а не выглядело потерей.

Аргументы: `uv run python scripts/gorouter_checkin.py [id аккаунтов] [домен станции]` —
числа считаются id записей, остальное именами станций, оба фильтра необязательны. Отчёт —
`log/gorouter_checkin.txt` секциями по станциям (отмечено X из Y, сколько принесло, баланс),
состояние — `log/gorouter_checkin_state.json`. В кроне `23 19 * * *`, вывод в
`log/gorouter_checkin_cron.txt`.

Статус `КЛИК` — не поломка: панель принимает клик и начисляет с задержкой, на gorouter так
заканчивается примерно половина аккаунтов, а через несколько минут `checked_in_today` уже
`true`. Отдельная застарелая болячка — OAuth изредка застревает на `/sign-in`; аккаунт
уходит в `НЕ ОТМЕЧЕН`, следующий прогон его добирает.
